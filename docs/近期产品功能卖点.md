# agentNote 近期产品功能卖点

## 一句话介绍

agentNote 让 Obsidian 里的本地资料直接参与 AI agent 的工作：选中资料交给 agent，成果再写回自己的笔记库。

## 核心卖点

### 1. 从 Obsidian 直接分享资料给 agent

在笔记或文件上右键，复制分享地址并粘贴给 agent，就能让它读取资料；也可以分享文件夹、笔记中的选段，或一次分享多个选中项目。多项分享会标明各自标题并清楚分隔，agent 更容易分辨每份资料。

**用户得到什么：** 不必反复上传附件、复制正文或解释文件在哪里。需要哪份资料，就从 Obsidian 把哪份资料交给 agent。

**适合的宣传表达：**「从 Obsidian 右键分享，让 AI 读懂你选的资料。」

### 2. AI 的成果写回自己的笔记库

接入 agent 后，可以直接说“写到 Obsidian”或“记到笔记里”。agent 能把对话中的结论整理成 Markdown 笔记，也能继续更新已有笔记。成果留在用户自己的 vault 中，下一次对话或换一个 agent 时仍可继续使用。

**用户得到什么：** AI 的产出不再只留在聊天记录里，而是成为可编辑、可整理、可再次分享的个人知识。

**适合的宣传表达：**「让 AI 做完的事，沉淀到你的笔记里。」

### 3. 同一套笔记，交给不同 agent 协作

接入台支持 Claude Code、Codex 和 WorkBuddy，并提供手动接入其他 agent 的方式。接入后，用户可以把同一套 Obsidian 资料用于不同任务：让一个 agent 阅读资料，让另一个 agent 整理结果，再把结果写回笔记库。

**用户得到什么：** 工作资料不必跟着某一个 AI 工具走，换 agent 也不用重建一套知识库。

**适合的宣传表达：**「换一个 agent，继续用你的知识工作。」

### 4. 看见知识真正参与了哪些工作

知识档案把本地新建、编辑、阅读，以及 agent 读取和写入等活动汇总起来。用户可以查看本周节奏、常用资料、每份资料的活动记录，并从档案直接打开原文件；也能生成可隐藏资料名称的知识贡献分享图。长期少用的资料会获得整理建议，由用户决定是否归档或保护。

**用户得到什么：** 不只知道自己存了多少笔记，还能看见哪些资料被使用、复用和继续建设。

**适合的宣传表达：**「让第二大脑的价值，看得见。」

### 5. 本地优先，资料仍由用户掌控

agentNote 运行在 Obsidian 桌面端，服务仅供本机访问。笔记和活动记录保存在用户自己的 vault 中；插件不要求账号，也不提供云端中转或公网分享。用户决定分享什么资料，原文件仍可继续用 Obsidian 和现有工具管理。

**用户得到什么：** 在使用 AI 协作的同时，保留本地文件的所有权和管理方式。

**适合的宣传表达：**「让 AI 用上你的本地知识，不必迁走你的知识。」

## 可直接用于产品介绍的文案

> 你的 Obsidian 笔记不该只停在收藏夹里。用 agentNote，从笔记中选出此刻需要的资料，右键分享给 AI agent；让它阅读、整理、完成任务，再把成果写回你的笔记库。你可以在知识档案里回看哪些资料真正参与了工作。内容始终保存在自己的 vault 中，Claude Code、Codex、WorkBuddy 或其他已接入的 agent 都能接着使用。

## 典型场景

- **资料整理：** 多选几份项目笔记交给 agent，让它提炼重点、待办和风险，再写回一份可持续更新的项目笔记。
- **跨 agent 接力：** 把已有方法或项目背景交给新的 agent，让它在同一套本地资料上继续工作。
- **知识回顾：** 在档案中查看本周真正被阅读、引用和更新的资料，打开原文继续完善，或整理长期少用的内容。

## 对外表述边界

agentNote 是 Obsidian 桌面端的本地协作插件。分享地址供本机 agent 使用，Obsidian 运行时才能访问；它不是面向他人的公网文件分享服务。对外描述隐私时，应说“agentNote 不提供云端中转”，不要保证第三方 agent 或模型不会处理它读取的内容。
