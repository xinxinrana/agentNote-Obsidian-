# Git 多设备活动记录

本次实现范围是操作日志的多设备存储与统计。文件分享仍是核心功能；正文、分享配置、文档索引和引用状态沿用现有机制，本次不实现整个 vault 的自动合并。

## 记录方式

每台设备在 `agentNote/data/events.<deviceId>.json` 中维护自己的 JSON 数组。新操作追加到数组末尾，不修改旧事件，不写入其他设备的日志。文件数量随设备数量增长，不随分享或读取次数增长。

每条新事件包含随机生成的 `eventId` 和本机 `deviceId`。所有活动统计入口读取 `events.*.json`，按 `eventId` 合并去重。重复拉取同一个日志不会增加次数；两次独立操作具有不同 ID，都会计入统计。

Git 第一次看到某设备的日志时显示新增文件，之后追加操作显示该文件被修改。不同设备拥有不同日志路径，因此各自追加操作时不会修改同一个活动日志。

## 本机身份

设备 ID 首次生成后保存到用户主目录的 `.agentnote/device-id`，不放进 vault 或插件配置目录。重启后沿用这个 ID，克隆同一个 vault 的另一台设备生成自己的 ID。该文件不保存笔记内容。

不要把本机 `device-id` 复制到另一台设备。这里的“设备”实际对应一个本机用户环境；如果同步了整个用户主目录，也要排除此身份文件。

## 旧数据与写入保护

- 原来的 `agentNote/data/events.json` 保留为只读历史，不移动、不删除、不复制到每台设备的新日志。
- 读取旧记录时临时生成确定性的事件 ID，不修改原文件。内容完全相同的两条旧操作也会保留为两条记录。
- 本机日志写入按顺序执行，并先写临时文件再替换正式文件，避免正常读取碰到半写入的 JSON。
- 本机日志格式损坏时拒绝追加，保留原文件；统计遇到损坏的日志会报错，不把它当成空历史。

## 使用与边界

同步 vault 时保留 `agentNote/data/events.*.json` 和已有的 `events.json`。Git 提交、拉取及正文冲突处理继续使用用户原有工具。

更新所有参与同步的设备上的插件。旧版插件仍会写入共享的 `events.json`，混用版本不能保证活动日志写入隔离。

本次不会消除 `shares.json`、`documents.json`、`references.json`、`agents.json`、`idempotency.json` 或 Markdown 正文的同步冲突，也不抑制 Git 拉取所触发的 Obsidian 文件活动。操作日志的 ID 去重能识别同一条已记录事件，不能自动认定两个设备分别观察到的文件变更属于同一个操作。

同一设备同时运行多个进程写入同一 vault，或者 Git 操作与正在写入的日志并发执行，不属于本次验证范围。同步时建议暂停对该 vault 的操作。

## 验证

`npm test` 覆盖设备身份持久化、两份 vault 的日志合并、旧历史兼容、重复导入去重、同进程并发追加和损坏日志保护。

`npm run test:git-sync` 使用临时 Git 仓库模拟两台设备从同一基线分别修改自己的已有日志，再执行真实 Git 合并，检查无冲突、记录完整、历史不变和重复合并不重复计数。需要本机安装 Git。
