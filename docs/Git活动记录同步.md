# Git 多设备活动记录

> English copy: [Git Activity Sync](Git%20Activity%20Sync.md)

操作日志按设备存储和统计，分享记录按链接独立存储；正文、文档索引和引用状态仍需按现有方式同步。本插件不自动合并整个 vault。

## 记录方式

每台设备在 `agentNote/data/events.<deviceId>.json` 中维护自己的 JSON 数组。新操作追加到数组末尾，不修改旧事件，不写入其他设备的日志。文件数量随设备数量增长，不随分享或读取次数增长。

每条新事件包含随机生成的 `eventId` 和本机 `deviceId`。所有活动统计入口读取 `events.*.json`，按 `eventId` 合并去重。重复拉取同一个日志不会增加次数；两次独立操作具有不同 ID，都会计入统计。

Git 第一次看到某设备的日志时显示新增文件，之后追加操作显示该文件被修改。不同设备拥有不同日志路径，因此各自追加操作时不会修改同一个活动日志。

## 本机身份

设备 ID 首次生成后保存到用户主目录的 `.agentnote/device-id`，不放进 vault 或插件配置目录。重启后沿用这个 ID，克隆同一个 vault 的另一台设备生成自己的 ID。该文件不保存笔记内容。

不要把本机 `device-id` 复制到另一台设备。这里的“设备”实际对应一个本机用户环境；如果同步了整个用户主目录，也要排除此身份文件。

## 旧数据与写入保护

- 原来的 `agentNote/data/events.json` 保留为只读历史，不移动、不删除、不复制到每台设备的新日志。
- 读取旧记录时临时生成确定性的事件 ID，不修改原文件。内容完全相同的两条旧操作也会保留为两条记录。
- 本机日志写入按顺序执行，并先写临时文件再替换正式文件，避免正常读取碰到半写入的 JSON。
- 本机日志格式损坏时拒绝追加，保留原文件；统计遇到损坏的日志会报错，不把它当成空历史。

## 使用与边界

在插件设置中可开启启动后延迟自动冷备份，或手动点击“立即备份”。备份只读取本机设备日志和旧版 `events.json`，将早于本机今天的事件按来源、按日期分别保存到 `agentNote/data/cold-backups/`。文件一旦生成便不会改写，也不会被插件用于统计；不同设备各自保存自己的日志。备份不包含 Markdown 正文及共享配置。迟到的旧日期记录不会回写已有快照。

本机日志的备份名为 `events.<deviceId>.<YYYY-MM-DD>.json`，例如 `events.abc123.2026-10-02.json`；旧版共享日志的备份名为 `events.legacy.<deviceId>.<YYYY-MM-DD>.json`。中间的 ID 是当前电脑在用户主目录中保存的设备 ID，用来区分不同电脑生成的备份。每台电脑只备份自己的新日志；多台电脑都能看见的旧版日志可能各自产生一份副本。恢复时需要按事件 ID 去重，旧版无 ID 的记录需结合内容和来源核对。

插件创建备份时使用“目标文件已存在就跳过”的方式，不会重建或修改已有日期的备份，也不修改源日志。这里的“不可改写”只约束插件自身：手动编辑、Git 操作或存储故障仍可能改变文件；需要保留 Git 历史或其他独立备份来核验和恢复。若某一天后来补入旧日期的事件，先前快照仍保持原样，新事件留在源日志中。

同步 vault 时保留 `agentNote/data/events.*.json` 和已有的 `events.json`。Git 提交、拉取及正文冲突处理继续使用用户原有工具。

更新所有参与同步的设备上的插件。旧版插件仍会写入共享的 `events.json`，混用版本不能保证活动日志写入隔离。

新分享保存在 `agentNote/data/shares/<分享ID>.json`，不会反复改写共享的 `shares.json`。已有的 `shares.json` 保留为只读历史，旧链接仍可读取；修改旧链接或移动其目标时，会为该链接建立独立记录，不改写旧文件。同步时要保留整个 `shares/` 目录及原有 `shares.json`。不同设备创建不同链接时，通常不会再修改同一个分享记录文件；同一链接在多设备上同时修改，仍需处理 Git 冲突。

若旧 `shares.json` 损坏，插件保留原文件，新分享和已有独立记录仍可创建、读取和修改；依赖该旧文件的链接会报错，修复旧文件后恢复。若某个独立分享文件损坏，仅该链接报错，其他链接仍可使用。列表会跳过损坏记录并输出日志，不能把列表中暂时缺少的记录当作已删除。

`documents.json`、`references.json`、`agents.json`、`idempotency.json` 和 Markdown 正文仍可能发生同步冲突；Git 拉取也可能触发 Obsidian 文件活动。操作日志的 ID 去重能识别同一条已记录事件，不能自动认定两个设备分别观察到的文件变更属于同一个操作。

读取损坏的共享 JSON 文件时，依赖它的操作会报错，不会把旧数据当作空数组或空对象覆盖。遇到错误时先检查并解决 Git 冲突，不要删除原文件来消除提示。

同一设备同时运行多个进程写入同一 vault，或者 Git 操作与正在写入的日志并发执行，不属于本次验证范围。同步时建议暂停对该 vault 的操作。

## 验证

`npm test` 覆盖设备身份持久化、两份 vault 的日志合并、旧历史兼容、重复导入去重、同进程并发追加和损坏日志保护。

`npm run test:git-sync` 使用临时 Git 仓库模拟两台设备分别追加操作日志、创建分享，再执行真实 Git 合并，检查无冲突、链接可用、记录完整且历史不变。需要本机安装 Git。
