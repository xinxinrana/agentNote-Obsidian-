# Git 同步下的可用性与历史改造方案

> English copy: [Git Sync Reliability Plan](Git%20Sync%20Reliability%20Plan.md) · [数据文件与同步边界](数据文件与同步边界.md)

## 目标与边界

按顺序保证：**插件能启动并提供读、分享、写服务；已有历史可查看；资料贡献和归档等辅助功能尽量可用**。单个索引或日志损坏不得拖垮前两项。用户的 Markdown 正文冲突不由 agentNote 解决；插件也不接管 Git 同步。

“可查看历史”包括诚实显示完整性：某个来源不可读时，展示其余记录和问题文件，不把部分统计冒充完整总数。修复前保留原始字节，不自动删除、重置或覆盖历史。

## 数据边界

| 类型 | 同步中的职责 | 写入原则 |
| --- | --- | --- |
| Markdown 正文、agentNote 笔记及分享定义 | 内容和链接的事实来源 | 沿用现有文件与 API；同一文件的编辑分歧不在本方案内。 |
| 新活动记录 | 可同步的操作事实，也是时间线和活动统计的来源 | 每条操作写入唯一命名的文件，发布成功后不再修改；按 `eventId` 去重。 |
| `events.json`、`events.<deviceId>.json` | 已有历史来源 | 新版只读，不迁移、删除或改写；旧版混用的限制明确提示。 |
| `documents.json` | 旧文档 ID、保护等状态的兼容来源 | 保留原文件，但从服务和历史的必需路径退出；新操作不再重写它。 |
| `references.json` | 旧引用比较基线 | 保留原文件；比较基线转为本机数据，当前链接仍从笔记／Obsidian 获取。 |
| 看板索引与统计缓存 | 加速展示的派生视图 | 本机可重建，不作为 Git 同步中的共同写入目标。 |

活动记录不复制正文。记录保存操作类型、时间、唯一 ID、设备、当时的标题与路径、可用的笔记／分享 ID 和 Agent 身份。移动记录还保存原路径；保护状态作为明确的用户选择记录，但不自动折算成活动分数。历史展示首先使用事件自身的快照字段，不要求成功读取文档索引或分享列表。

## 实施顺序

### 1. 服务与历史解除索引依赖

- `src/core/server.ts`：`agents.json` 读取失败时保留错误提示，身份归因暂用请求已上报的名称／ID，不让故障发生在所有业务路由之前。登记或同一幂等键状态无法安全判断时，该操作单独报错，不让无关请求失败。
- `src/core/store.ts`：本地创建、编辑、阅读、移动、删除的历史先依据事件自带路径和标题写入；`documents.json` 不可用不阻止记录。新建、更新和分享的成功不依赖贡献索引或历史写入；历史写入失败必须提示，不能悄悄声称已记录。
- `src/core/store.ts`：将活动汇总与资料贡献／归档计算拆开。时间线、近况、每日活动和 Agent 活动仅依赖日志；旧文档索引异常时，仅资料贡献／归档区域降级，并标明原因。
- `src/ui/panel.ts`：档案弹窗和接入台分别处理加载错误；档案的时间线与活动概览在索引异常时仍可打开。诊断入口指出具体文件，恢复后可重试。

### 2. 活动记录改为不可变写入

- `src/core/activityLog.ts`：新事件写入 `agentNote/data/events/<年月>/<eventId>.json`。生成随机 ID，先写临时文件，再原子发布为不存在的目标；发布失败不能覆盖已有文件。旧版两类数组只读保留。
- 读取返回事件和来源问题清单。某文件含 Git 冲突标记、JSON 无效或结构无效时跳过**该来源的展示**、保留文件并报告；其他来源继续显示。相同 `eventId` 且内容相同只展示一次，内容不同则报告冲突，不能随意挑一个。
- 完整统计只在全部来源可读时标为完整；缺失来源时仅显示“已知记录／部分结果”。新文件目录按月份分层；本机可重建索引避免每次打开档案都重新解析全部文件。
- 冷备份覆盖新记录；备份只做保全，不参与普通统计，也不自动覆盖来源。

### 3. 退出共享可变索引

- `src/core/store.ts`：`documents.json` 只读兼容旧 ID 和保护状态。新文档由 vault 文件及操作记录建立视图；已有事件按原 `documentId` 展示，缺少对应索引时仍按事件的标题／路径展示。阅读不产生“文档更新”，`updated` 从有意义的维护活动计算，不再为了刷新时间而写共享数组。
- 保护／取消保护等用户选择写入不可变记录；健康旧数据中的保护状态继续生效。对同一文档出现不能判断的相反操作时，保留记录并在辅助界面提示确认，不阻断读写和历史。
- `references.json` 不再作为共享写入目标。本机首次建立链接比较基线时不产生“新增引用”；无变化不写入；不能确认是本机编辑还是 Git 同步的变化不冒充用户操作。
- `agents.json` 和 `idempotency.json` 不再由无关操作共同改写一个全局对象：身份登记按 Agent 隔离；幂等状态按请求键隔离。同一键状态损坏或跨设备离线重用时，不承诺无法验证的“恰好一次”。
- 现有 `shares/<分享ID>.json` 继续承担链接定义，不因为上述迁移改变分享 URL。同一链接的并发修改另行提示，不影响新链接。

### 4. 兼容、恢复与发布门槛

- 不就地改写或删除旧 `documents.json`、`references.json`、活动数组、分享记录；首次运行不因暂时缺文件而创建空文件覆盖待同步状态。修复仍先备份原字节，仅自动处理能明确证明结果正确的情况。
- 新版可读新旧历史；旧版不认识新格式，降级到旧版可能暂时看不到新增历史，但文件仍在，重新升级即可恢复。参与同一 vault 同步的设备应全部更新，混用旧版期间不能承诺无插件数据冲突。
- 先在临时 Git 仓库和独立测试 vault 验证；本机部署仅指向“测试”库。用户确认实际使用后再讨论提交、推送或发布。

## 回归与验收

| 场景 | 必须得到的结果 |
| --- | --- |
| A 离线阅读／分享，B 离线创建／更新，之后双向 Git 合并 | 插件新活动文件无同路径争写；双方历史各保留一次，分享继续可用。 |
| 同一电脑上的两个 vault 副本记录活动 | 即使共用设备 ID，也不会争写同一个新活动文件。 |
| `documents.json` 损坏或含冲突标记 | 服务、分享、写入与已有时间线可用；仅相关辅助区域标明不可用，原文件字节不变。 |
| `references.json` 或 `agents.json` 损坏 | 无关的内容 API 与历史不被阻断；身份／引用功能显示具体问题。 |
| 一份旧日志或新事件文件损坏 | 其余记录可见，统计标记为部分结果；损坏文件原样保留。 |
| 活动日志无法写入 | 内容操作结果如实返回，同时明确提示“本次活动未记录”；不能伪造一条成功历史。 |
| Git 同步触发文件事件 | 不把另一台设备已记录的操作再次计作本机明确操作；来源无法判断时不虚构用户行为。 |
| 旧历史、保护状态、分享 URL 与可修复冲突 | 升级后仍可读取；不能确定的状态不自动合并或删除。 |
| 大量历史记录与多次打开档案 | 服务启动不等待全量统计；本机索引可删除后重建，结果与直接读取一致。 |

验收使用临时文件、两份 vault 副本和真实 Git 分支合并；不以用户实际 vault 的 JSON 做破坏性试验。归档建议的准确性在核心可用、历史完整性和数据保全通过后单独验收。
