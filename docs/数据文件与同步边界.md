# 数据文件与多设备同步边界

> English copy: [Data Files and Sync Boundaries](Data%20Files%20and%20Sync%20Boundaries.md)

agentNote 不负责同步 vault；哪些文件进入 Git 由用户决定。笔记正文仍以 Markdown 为准。同步时应保留完整的 `agentNote/` 目录，不要为了消除报错而删除损坏文件。

## Vault 内的数据

以下路径相对于 vault 根目录。

| 文件 | 用途与写入边界 |
| --- | --- |
| `agentNote/nodes/*.md` | agentNote 笔记正文与元信息。同一篇正文的并发编辑仍由 Obsidian／Git 工作流处理。 |
| `agentNote/data/shares/<分享 ID>.json` | 每条分享链接的定义。新建不同链接不会争写同一文件；同一链接的并发修改或目标移动仍可能冲突。其他完好的链接继续可用。 |
| `agentNote/data/shares.json` | 旧版分享链接，只读兼容。 |
| `agentNote/data/events/<年-月>/<事件 ID>.json` | 一次活动一个不可变文件；含时间、设备、活动类型、标题／路径快照及可用的笔记、文档、分享和 Agent ID。按事件 ID 去重。损坏的单条记录不遮住其他来源；看板会标明统计不完整。 |
| `agentNote/data/events.json`、`events.<设备 ID>.json` | 旧版活动数组，只读兼容，不原地迁移或重写。某个来源损坏时保留原字节，其他来源继续展示。旧版本插件仍可能改写它们，因此同步同一 vault 的设备应统一升级。 |
| `agentNote/data/documents.json` | 旧版文档 ID、路径与保护状态，只读兼容。新操作从活动记录和 vault 文件重建文档视图；读取不更新文档时间，保护状态写入独立活动记录。旧文件损坏时内容服务与时间线继续工作，归档建议停用，相关统计标明不完整。 |
| `agentNote/data/references.json` | 旧版链接比较基线，只读兼容。当前链接仍从笔记和 Obsidian 索引获得；本机基线不再跨设备争写。 |
| `agentNote/data/agents.json` | 旧版 Agent 身份登记，只读兼容。损坏时退回请求上报的身份，不阻断读写和分享。 |
| `agentNote/data/agents/<ID 哈希>.json` | 每个 Agent 独立登记；不同 Agent 不争写同一文件，同一 ID 的离线不同名称仍可能冲突。 |
| `agentNote/data/idempotency.json` | 旧版幂等键索引，只读兼容。损坏时仅带幂等键的创建不能安全确认，普通创建及其他服务不受影响。 |
| `agentNote/data/idempotency/<键哈希>.json` | 每个幂等键独立关联笔记 ID。不同键互不争写；两台离线设备重用同一键不能保证全局恰好创建一次。 |

## 本机状态与备份

| 文件 | 用途与边界 |
| --- | --- |
| 用户主目录 `.agentnote/device-id` | 本机设备身份，不随 vault 同步。共享设备 ID 也不会使新活动写入同一文件。 |
| 用户主目录 `.agentnote/references.<vaultHash>.json` | 按 vault 路径区分的本机引用比较基线。首次观察只建立基线，不计新增引用；无变化时不写入。Git 带来的单独链接变化与本机编辑无法总是可靠区分。 |
| 用户主目录 `.agentnote/connections.<vaultHash>.json` | 本机 Agent 接入及 Skill 路径；绝对路径通常不适合跨设备同步。 |
| `agentNote/data/cold-backups/` | 早于今天的活动冷备份，只创建、不覆盖；不参与实时统计，也不是完整 vault 备份。 |
| `agentNote/data/repair-backups/*.bak` | 自动修复前保存原文件的准确字节，不参与实时统计。 |
| Obsidian 插件目录 `data.json` | 语言、端口、启动及其他插件偏好；实际目录以 vault 的 `configDir` 为准。 |

## 故障与同步边界

1. 优先保持插件启动与完好资料的读取、分享、写入；活动记录写入失败不伪造成功历史，界面提示未记录。
2. 其次保全数据。缺失的旧可选索引不自动创建空文件；可确认的修复先备份原始字节，不能确认的分歧交给用户处理。
3. 可读的历史继续展示。旧日志或单条新记录损坏时，统计是**部分结果**，不能当作完整总数；看板标明问题来源。
4. 归档建议依赖完整历史和文档状态；来源不完整时停用。相反的文档操作、同一分享链接的并发修改、同一幂等键的离线重用，以及 Markdown 正文冲突，不能靠拆文件自动消除。

Obsidian 的文件通知不包含“用户操作”或“Git 同步”的来源标记。插件不会声称仅凭文件通知就能可靠区分两者；Git 拉取后的本地文件事件仍可能形成额外活动记录。

“检查并修复”会检查现存的旧文档／引用索引、旧日志和新活动文件；只自动处理能确定结果的文档索引冲突，不会清空损坏文件。
